3. Fonte de Dados — trilhas_dio.json

O arquivo dio_explorer/data/trilhas_dio.json é o único ponto de verdade do projeto. Contém 32 trilhas com o seguinte schema por objeto:

{
  "id": 1,
  "nome": "Fundamentos de Python para Iniciantes",
  "tecnologia": "Python",
  "nivel": "Básico",           // Básico | Intermediário | Avançado
  "numero_de_modulos": 6,
  "xp_total": 4200,
  "badges_disponiveis": ["Python Rookie", "Code Starter", "Logic Builder"],
  "promocoes": {               // null se não houver promoção
    "desconto": "30%",
    "validade": "2025-08-31",
    "cupom": "PYTHON30"
  },
  "vitalicio": true,
  "lives_ao_vivo": [
    { "titulo": "Introdução ao Python", "data": "2025-07-10", "horario": "19:00" }
  ]
}
Design Decision O campo promocoes pode ser null — uma escolha intencional para testar o caminho negativo (TC-18: sem promoção exibe mensagem padrão). Tanto o Python quanto o TypeScript tratam esse caso explicitamente.

4. Slash Commands

Slash commands são arquivos .md em .bob/commands/. O nome do arquivo define o comando. Argumentos digitados após o comando são mapeados em $1, $2, etc.

/trilha <tecnologia>

Busca uma trilha no catálogo (busca parcial, case-insensitive) e exibe o plano de estudos completo em Markdown com módulos, badges, lives e promoção.

Exemplos

/trilha Python
/trilha java
/trilha react
/trilha watsonx
/trilha docker

Comportamento de Erro

Se a tecnologia não for encontrada, o Bob lista todas as tecnologias disponíveis no catálogo de forma amigável.

/desafio [tecnologia] [nivel: Básico|Intermediário|Avançado]

Gera um desafio de código aleatório. Se omitir os argumentos, o Bob sorteia tecnologia e nível do catálogo automaticamente.

Exemplos

/desafio Python Básico
/desafio Java Intermediário
/desafio React Avançado
/desafio                    ← sorteia automaticamente

XP por Nível

NívelXP MínimoXP Máximo
Básico200 XP500 XP
Intermediário500 XP1.000 XP
Avançado1.000 XP2.000 XP
/certificado <seu-nome> <tecnologia>

Gera um certificado fictício de conclusão com dados reais da trilha, data atual e ID único no formato DIO-NNN-AAAA-NNNNNN.

Exemplos

/certificado Fabricio Eirim Castro Python
/certificado Ana Paula Java
/certificado Carlos React
/certificado Maria Souza watsonx
⚠️ Certificado Fictício Gerado exclusivamente para fins educacionais e demonstração no contexto deste projeto.

5. Prompts Utilizados

A seguir estão os prompts exatos que geraram as diferentes partes do projeto. Estes prompts são a documentação mais valiosa para quem quer aprender a trabalhar com IA.

Criação do Catálogo de Dados

Prompt — trilhas_dio.json
Crie um arquivo JSON chamado trilhas_dio.json com 32 trilhas de aprendizado simulando a plataforma DIO. Cada trilha deve ter: id, nome, tecnologia, nivel (Básico/Intermediário/Avançado), numero_de_modulos, xp_total, badges_disponiveis (array), promocoes (objeto com desconto/validade/cupom ou null), vitalicio (boolean) e lives_ao_vivo (array com titulo/data/horario). Inclua tecnologias variadas como Python, Java, React, AWS, watsonx, Docker, Machine Learning, etc.

Slash Command /trilha

Prompt — .bob/commands/trilha.md
Crie um slash command /trilha que leia o arquivo trilhas_dio.json, faça busca parcial case-insensitive pelo campo tecnologia com o argumento $1, e retorne o plano de estudos formatado em Markdown com cabeçalho, módulos gerados contextualmente, badges, lives ao vivo e promoção. Se não encontrar, liste as tecnologias disponíveis.

Slash Command /desafio

Prompt — .bob/commands/desafio.md
Crie um slash command /desafio com argumentos opcionais $1 (tecnologia) e $2 (nivel). Se nenhum argumento for passado, sortear do catálogo. O desafio deve ter título criativo, descrição clara, requisitos, exemplo de entrada/saída, critérios de avaliação, tempo sugerido e XP proporcional ao nível (Básico: 200-500, Intermediário: 500-1000, Avançado: 1000-2000).

Slash Command /certificado

Prompt — .bob/commands/certificado.md
Crie um slash command /certificado <nome> <tecnologia> que gere um certificado fictício em Markdown com nome do usuário ($1), dados reais da trilha encontrada por $2, data atual do sistema formatada DD/MM/AAAA, e ID único no formato DIO-{id}-{ano}-{6 dígitos aleatórios}. Incluir todas as badges da trilha e aviso de que é fictício.

Módulo Python + Testes

Prompt — trilhas_utils.py + test_slash_commands.py
Crie o módulo Python trilhas_utils.py com funções puras (sem I/O de rede) implementando as regras de negócio dos slash commands: carregar_trilhas(), buscar_trilha(), formatar_plano_estudos(), gerar_desafio() e gerar_certificado(). Em seguida, crie uma suíte de testes pytest com cobertura >= 70%, testando todos os caminhos: busca exata, case-insensitive, parcial, string vazia, nível inválido, formato do ID do certificado, e um fluxo integrado completo (TC-36).

MCP Server

Prompt — dio_explorer/mcp/src/index.ts
Crie um servidor MCP em TypeScript usando @modelcontextprotocol/sdk e zod que exponha as mesmas três ferramentas dos slash commands: trilha_buscar, desafio_gerar e certificado_gerar. Use transporte stdio, leia os dados de trilhas_dio.json, valide os inputs com zod e retorne conteúdo Markdown formatado. Compile com tsc e registre em .bob/mcp.json.

Documentação dos Slash Commands

Prompt — .bob/commands/README.md
Crie uma documentação completa em Markdown dos três slash commands em .bob/commands/README.md explicando como funcionam os slash commands, sintaxe de cada um, exemplos de uso, o que é retornado, tabelas de parâmetros, lista completa das 32 trilhas disponíveis e estrutura de arquivos do projeto.

6. Módulo Python — trilhas_utils.py

O módulo dio_explorer/src/trilhas_utils.py encapsula toda a lógica de negócio em funções puras — sem dependências externas, sem I/O de rede, totalmente testáveis.

FunçãoResponsabilidadeRetorno
carregar_trilhas(caminho)Lê e parseia o JSONlist[dict]
buscar_trilha(tecnologia, trilhas)Busca parcial case-insensitivedict | None
formatar_plano_estudos(trilha)Gera Markdown do planostr
gerar_desafio(tecnologia, nivel)Sorteia desafio, gera XPdict
gerar_certificado(nome, trilha, hoje)Gera certificado Markdownstr
Padrão de Design: Injeção de Dependência para Testabilidade A função gerar_certificado aceita o parâmetro opcional hoje: Optional[date] = None. Isso permite que os testes passem uma data fixa (date(2025, 7, 10)) garantindo resultados determinísticos, enquanto em produção a data atual é usada automaticamente. Esse padrão é chamado de dependency injection e é fundamental em código testável.

7. MCP Server — dio-explorer

O Model Context Protocol (MCP) permite que o Bob use ferramentas externas como se fossem capacidades nativas. O servidor dio-explorer-mcp é registrado no arquivo .bob/mcp.json e expõe 3 ferramentas via transporte stdio.

Registro no Bob (.bob/mcp.json)

{
  "mcpServers": {
    "dio-explorer": {
      "command": "node",
      "args": ["...caminho.../dio_explorer/mcp/build/index.js"]
    }
  }
}

Ferramentas Expostas

Nome MCPDescriçãoParâmetros Zod
trilha_buscarBusca trilha e retorna plano em Markdowntecnologia: z.string()
desafio_gerarGera desafio de código aleatóriotecnologia: z.string(), nivel: z.enum([...])
certificado_gerarGera certificado fictícionome: z.string(), tecnologia: z.string()

Build e Execução

# Instalar dependências
cd dio_explorer/mcp
npm install

# Compilar TypeScript
npm run build    # gera build/index.js

# Testar diretamente (opcional)
npm start
Slash Command vs MCP Tool Os slash commands são prompts de linguagem natural executados pelo Bob. As ferramentas MCP são código executável chamado programaticamente. A grande vantagem do MCP é que o Bob pode encadear ferramentas automaticamente em tarefas complexas sem que o usuário precise digitar nada.

Caso de Teste Integrado (TC-36)

O TC-36 simula o fluxo completo de um usuário chamando os três comandos em sequência:

# 1. Carregar catálogo → 32 trilhas
trilhas = carregar_trilhas(caminho)

# 2. /trilha java → encontra "Desenvolvedor Java Full Stack"
trilha = buscar_trilha("java", trilhas)

# 3. Gerar plano de estudos
plano = formatar_plano_estudos(trilha)   # contém "Java"

# 4. /desafio Java Intermediário → XP >= 500
desafio = gerar_desafio(trilha["tecnologia"], trilha["nivel"])

# 5. /certificado → ID: DIO-002-2025-XXXXXX
cert = gerar_certificado("Fabricio Eirim Castro", trilha, date(2025, 7, 10))

9. Dicas de Uso do IBM Bob

Slash Commands

💬

Seja específico

Use /trilha watsonx em vez de buscar "IA IBM" — o campo tecnologia é o que é buscado no JSON.

🔍

Busca parcial funciona

/trilha java, /trilha JAVA e /trilha Ja retornam o mesmo resultado graças à busca case-insensitive.

🎲

Surpresa no /desafio

Digite apenas /desafio sem argumentos para o Bob sortear tecnologia e nível do catálogo — ótimo para praticar fora da zona de conforto.

🏆

Nomes compostos no /certificado

/certificado Fabricio Eirim Castro Java — o último token é sempre a tecnologia; o restante é o nome.

Trabalhando com o Bob em Geral

📋

Peça listas de TODO

Inicie projetos pedindo "crie uma lista de tarefas para construir X". O Bob mantém a lista atualizada conforme avança.

🔄

Itere em cima do código existente

Diga "agora adicione testes" ou "refatore para funções puras" — o Bob lê o arquivo atual antes de editar.

🧪

Peça testes junto com o código

Sempre solicite "crie também os testes unitários" no mesmo prompt que pede a implementação — isso força cobertura desde o início.

📁

Use o .bobignore

Coloque node_modules/, .env e pastas de cache no .bobignore para manter o contexto relevante e rápido.

🛠️

Modo Plan antes de codar

Para projetos complexos, use o modo Plan primeiro para definir a arquitetura antes de entrar no modo Agent para implementar.

🔌

MCP amplifica o Bob

Um servidor MCP transforma o Bob em um agente que pode consultar dados externos, executar código e encadear operações automaticamente.

10. Insights para Futuros Profissionais

Sobre IA como Copiloto de Desenvolvimento

O Bob não substitui o desenvolvedor — ele amplifica Todo o código deste projeto passou por revisão, refinamento e validação humana. A IA propõe; o desenvolvedor decide. O valor está em acelerar iterações, não em eliminar o julgamento humano.
🏗️

Arquitetura separada de interface

A lógica de negócio (trilhas_utils.py) foi separada da interface (slash commands e MCP). Isso permitiu testar 100% do código sem precisar simular o Bob.

🌐

MCP é o futuro das ferramentas de IA

O Model Context Protocol padroniza como LLMs interagem com sistemas externos. Aprender a construir servidores MCP é uma habilidade valiosa em 2025.

📝

Prompts são código

Os arquivos .md dos slash commands são literalmente o "código-fonte" dos comandos. Versioná-los no Git é tão importante quanto versionar Python ou TypeScript.

🧩

Funções puras = testabilidade

Todas as 5 funções de negócio são puras: mesma entrada, mesma saída, sem efeitos colaterais ocultos. Isso é o que permitiu 100% de cobertura com 36 testes simples.

🔗

Bilinguismo (Python + TypeScript)

O mesmo algoritmo foi implementado em Python (para testes) e TypeScript (para o MCP). Comparar as duas implementações é um excelente exercício de aprendizado.

📊

JSON como contrato de dados

O trilhas_dio.json serviu tanto para Python quanto para TypeScript sem adaptações. Um schema bem definido é a cola entre linguagens e sistemas diferentes.

Lições do Processo de Desenvolvimento

  1. Comece pelo dado: definir o schema do JSON antes de escrever qualquer código evitou retrabalho em todas as camadas.
  2. Slash commands primeiro: prototipar a interação como prompt simples antes de criar o MCP permite validar a ideia com custo zero.
  3. Testes como especificação: os testes (especialmente o TC-36 integrado) documentam exatamente o que o sistema deve fazer — melhor que qualquer comentário.
  4. Injeção de dependência para datas: sempre que uma função depende do "tempo atual", parametrize-a — isso torna os testes determinísticos sem mocks complexos.
  5. MCP na última etapa: a camada MCP foi a última a ser construída, quando a lógica já estava sólida e testada. Nunca construa a integração antes da lógica.
